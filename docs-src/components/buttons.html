Base class

felt-css has a base .btn class that sets up basic styles such as padding and content alignment. On its own, .btn is a plain, borderless button with a quiet hover, useful for secondary actions such as “Cancel”.

The .btn class is intended to be used in conjunction with the button variants, or to serve as a basis for your own custom styles.

Variants

felt-css includes several button variants, each serving its own semantic purpose, with a few extras thrown in for more control.

Conveying meaning to assistive technologies. Using color to add meaning only provides a visual indication, which will not be conveyed to users of assistive technologies like screen readers. Make sure the meaning is obvious from the content itself (e.g., the visible text of a button), or is included through alternative means, such as additional text hidden with the .visually-hidden class.

In the felt look every filled button is a patch of saturated felt, sewn on with a running stitch in a lighter tone of its colour. Pressed, it sinks into the felt instead of darkening; disabled, it goes pale and flat rather than see-through. Outline buttons are patches of plain felt, sewn on with thread in the button's colour (tone-on-tone in Firefox).

Disable text wrapping

Unlike Bootstrap's, felt-css buttons don't wrap their text by default (white-space: nowrap). If you want long labels to wrap, add the .text-wrap class to the button.

Button tags

The .btn classes are designed to be used with the <button> element. However, you can also use these classes on <a> or <input> elements (though some browsers may apply a slightly different rendering).

When using button classes on <a> elements that are used to trigger in-page functionality (like collapsing content), rather than linking to new pages or sections within the current page, these links should be given a role="button" to appropriately convey their purpose to assistive technologies such as screen readers.

Pill and icon buttons

Two extras that Bootstrap doesn't have. .btn-pill gives a button fully rounded ends; it works with every variant and size.

.btn-icon makes a round, square-sized button (2.75rem) without padding, for a single icon. Since there is no visible text, always add an aria-label.

For a bigger round button, set its width and height. In the felt look the seam of a round piece (.btn-icon, or any sewn piece with .rounded-circle) is drawn for its size, so it follows the circle at every size. Use .rounded-circle, not .rounded-pill, to make other pieces round: a pill's seam can't tell that its box is square.

Colour swatches

Another extra: .btn-swatch fills a button with the colour in --swatch. Round ones (.btn-icon) after .btn-check radios make a colour picker: the chosen swatch keeps its colour and gets a ring in the text colour (the focus ring takes its place while it has focus). A gradient, such as a colour wheel, goes in --swatch-image, over the colour. Name each colour in the label, hidden with .visually-hidden, and keep at least .gap-2 between swatches so the ring has room.

In the felt look a swatch is a patch of felt dyed in its colour and sewn on tone on tone, like the filled buttons; a white or cream one is cut from the cream felt, like the light pieces. The chosen one is circled, a few millimetres off, by a running stitch in the text's colour, sewn into the felt around it.

Icons and labels

A text label flows like Bootstrap's: .btn is an inline-block, so a label made of text and spans keeps its spaces. A button with a direct <svg>, <img>, .icon, .bi, badge or spinner child becomes an inline-flex row instead: icon and text centred, .4em apart, without spacing utilities.

Disabled state

Make buttons look inactive by adding the disabled boolean attribute to any <button> element. Disabled buttons have pointer-events: none applied to, preventing hover and active states from triggering.

Disabled buttons using the <a> element behave a bit different:

  • <a>s don’t support the disabled attribute, so you must add the .disabled class to make it visually appear disabled.
  • pointer-events: none disables the link functionality for the mouse.
  • Disabled buttons using <a> should include the aria-disabled="true" attribute to indicate the state of the element to assistive technologies.
  • Disabled buttons using <a> should not include the href attribute.

Link functionality caveat

To cover cases where you have to keep the href attribute on a disabled link, the .disabled class uses pointer-events: none to try to disable the link functionality of <a>s. Keyboard navigation remains unaffected, though, meaning that sighted keyboard users and users of assistive technologies will still be able to activate these links. So to be safe, in addition to aria-disabled="true", also include a tabindex="-1" attribute on these links to prevent them from receiving keyboard focus, and use custom JavaScript to disable their functionality altogether.

Button plugin

Bootstrap's button plugin allows you to create simple on/off toggle buttons.

Visually, these toggle buttons are identical to the checkbox toggle buttons. However, they are conveyed differently by assistive technologies: the checkbox toggles will be announced by screen readers as “checked”/“not checked” (since, despite their appearance, they are fundamentally still checkboxes), whereas these toggle buttons will be announced as “button”/“button pressed”. The choice between these two approaches will depend on the type of toggle you are creating.

Toggle states

Add data-bs-toggle="button" to toggle a button’s active state. If you’re pre-toggling a button, you must manually add the .active class and aria-pressed="true" to ensure that it is conveyed appropriately to assistive technologies.

JavaScript behavior

felt-css is CSS only; toggling comes from Bootstrap's button plugin. The methods (toggle, dispose, getInstance, getOrCreateInstance) work exactly as described in Bootstrap's button documentation.
