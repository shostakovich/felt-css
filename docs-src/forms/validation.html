How it works

Here's how form validation works with felt-css:

  • felt-css styles validation explicitly: add .is-valid or .is-invalid to a .form-control or .form-select, for example when your server renders the form again after a failed submit. The field gets a green or red border and a matching focus ring.
  • A .valid-feedback / .invalid-feedback (or -tooltip) element that follows the field as a sibling is shown automatically; otherwise it stays hidden.
  • There is no .was-validated: felt-css does not style the :valid and :invalid pseudo-classes, so a required field never shows up as invalid on page load. If you validate in the browser, toggle .is-invalid from JavaScript (see below).
  • Due to constraints in how CSS works, we cannot apply styles to a <label> that comes before a form control in the DOM without the help of custom JavaScript.
  • All modern browsers support the constraint validation API, a series of JavaScript methods for validating form controls. You may provide custom validity messages with setCustomValidity in JavaScript.

Browser defaults

Not interested in custom validation feedback messages or writing JavaScript to change form behaviors? All good, you can use the browser defaults: mark fields as required (or use type, pattern, min…) and leave out novalidate. Try submitting the form below. Server side

When your server validates the form, indicate invalid and valid form fields with .is-invalid and .is-valid. A following .invalid-feedback or .valid-feedback is shown with them.

For invalid fields, ensure that the invalid feedback/error message is associated with the relevant form field using aria-describedby (noting that this attribute allows more than one id to be referenced, in case the field already points to additional form text).

Input groups don't wrap in felt-css, and there is no .has-validation: place the feedback after the .input-group and show it with .d-block. The same goes for checkboxes: put the feedback after the .form-check.

Supported elements

Validation styles are available for the following form controls and components:

  • <input>s and <textarea>s with .form-control (including file inputs, and up to one .form-control in input groups)
  • <select>s with .form-select
  • Floating labels

.form-check-input has no valid or invalid style; give checkboxes and radios a feedback message instead.

Tooltips

If your form layout allows it, you can swap the .{valid|invalid}-feedback classes for .{valid|invalid}-tooltip classes to display validation feedback in a styled tooltip. Be sure to have a parent with position: relative on it for tooltip positioning; in the example below, .position-relative on the columns does that. Client side with JavaScript

To validate in the browser with your own messages, add novalidate to the <form> (this switches off the browser's feedback bubbles but keeps the validation API) and mirror each field's validity into .is-invalid when the form is submitted:

for (const form of document.querySelectorAll('.needs-validation')) { form.addEventListener('submit', event => { if (!form.checkValidity()) { event.preventDefault() event.stopPropagation() } for (const field of form.querySelectorAll('.form-control, .form-select')) { field.classList.toggle('is-invalid', !field.checkValidity()) } }) }
