CSS variables

felt-css is plain CSS: every colour, radius, space and shadow is a custom property. Override them to make the toolkit yours — no Sass, no build.

Naming#

Like Bootstrap's --bs-*, every public variable of felt-css starts with --felt-, so it doesn't collide with your own --primary or --border:

  • Global variables on :root: --felt-primary, --felt-radius, --felt-body-bg … (on this page).
  • Component variables on the component, named after Bootstrap's: .btn has --felt-btn-bg where Bootstrap has --bs-btn-bg. Each component page lists them under “CSS”.
  • Felt variables that only act in the felt look carry a material word: texture, sheet, nap, wool, patch, groove, seam, thread or stitch (--felt-thread-strength, --felt-patch-shadow). A plain word like --felt-shadow is always a variable of both looks. See Felt.
  • --_name variables are internal: they may change in any release.

The tables below are generated from the same source as felt.css; the Bootstrap column names the Bootstrap variable each one stands for.

Overriding#

All global variables live in @layer tokens. Any unlayered rule of yours wins over them, so overriding is just redefining:

:root {
  --felt-font: "Atkinson Hyperlegible", system-ui, sans-serif;
  --felt-radius: 6px;
  --felt-container-max: 1200px;
}

Variables can also be overridden on any element for that part of the page, like Bootstrap's component variables:

Badge 
<div style="--felt-primary: var(--felt-moss); --felt-primary-ink: #fff">
  <button type="button" class="btn btn-primary">Moss instead of denim</button>
  <span class="badge text-bg-primary">Badge</span>
</div>

Variables that differ between the looks (most colours, the radii) are set on :root for clean and again on :root[data-look="felt"]. To change a value for one look only, override it there: :root[data-look="felt"] { --felt-radius: 16px; }.
